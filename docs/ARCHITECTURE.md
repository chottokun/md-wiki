# アーキテクチャ解説：Raw + Compiled Hybrid RAG

RAG-Wiki が従来の RAG システムと決定的に異なるのは、その「情報の持ち方」にあります。

## 1. 2段階インデックス・システム
本システムは、Qdrant 内に以下の 2 種類のデータを保持します。

### A. 原始資料レイヤー (Raw Source)
- **内容**: Docling によって PDF から抽出された生の全テキスト。
- **目的**: AI が Wiki を書く際に削ぎ落としてしまった「極めて詳細な事実（数値、固有名詞、マイナーな注釈）」を保持するため。
- **検索時**: 質問に対する「直接的なエビデンス」として機能。

### B. コンパイル済みナレッジ・レイヤー (Wiki Page)
- **内容**: 人間がレビューし、AI が重要性を整理した Wiki ページ。
- **目的**: トピック全体の概要、他のページとの関連性、および人間の主観的な考察を保持するため。
- **検索時**: 質問に対する「コンテキスト（文脈）と解釈」を提供。

## 2. 知識のコンパイル・フロー
1. **Ingestion**: 生データを Markdown へ。
2. **Drafting**: Qdrant から関連する「Raw」と「Wiki」の両方を検索。AI がそれらを融合して新ページを起稿。
3. **Approval**: 人間が内容を確定。
4. **Synchronization**: 確定した Wiki ページをチャンク化して Qdrant へ再登録。同時に元の PDF を Vault 内にリンク・移動。

## 3. 履歴による自律的整理 (Git-driven Maintenance)
- Wiki の `wiki/.git` 履歴を AI がスキャン。
- 頻繁に更新される「ホット・ページ」を Synthesis (統合) の優先対象とし、放置された「コールド・ページ」を Lint (健康診断) であぶり出します。
- これにより、情報の鮮度が機械的に判定され、ナレッジベースが常に「新鮮な状態」に保たれます。
