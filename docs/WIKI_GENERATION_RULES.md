# Wiki生成・運用ルール (Wiki Generation Rules)

本ドキュメントは、エージェント（AI）がWikiページをどのように生成し、更新・維持すべきかという**設計・ルール**を明文化したものです。これは単なるマニュアルではなく、システムのPydanticスキーマおよびLLMプロンプトの設計根拠となります。

---

## 1. ディレクトリ構造

- `wiki/` (直下): 投入されたソース（PDF等）から生成される**メイン記事**。
- `wiki/concepts/`: メイン記事内で言及された技術用語や概念を解説する**概念ページ**。

---

## 2. メタデータの厳格管理 (Metadata Governance)

すべてのWikiページは、YAMLフロントマターにおいて Pydantic スキーマ (`WikiFrontmatterSchema`) に基づく OKF v0.1 (Open Knowledge Format) 準拠の厳格な構造を持ちます。

### 2.1 OKF 必須プロパティ
- **`type`**: OKF 規定の記事分類タイプ（`Concept`, `Article`, `Source`, `RawSource` など）。

### 2.2 OKF 推奨プロパティ
- **`title`**: 記事の人間向け表示名。
- **`description`**: ページの核心を突く具体的な概要（旧 `abstract`）。最低3行以上を要求し、「自動生成スタブ」などのプレースホルダーは禁止。
- **`resource`**: 原資料やエンティティを一意に識別するURI。
- **`tags`**: 分類タグ。新規生成時は必ず `[未審査]` を含める。
- **`timestamp`**: 最終更新日時（ISO 8601形式、旧 `updated`）。

### 2.3 拡張プロパティ (md-wiki 独自拡張)
- **`aliases`**: **重要：** ページタイトルそのものの「完全な別名」または「略称」のみを許可する。関連用語や類似概念をここに含めてはならない。
- **`concepts`**: 本文中の主要な概念や関連用語のリスト。
- **`created`**: ページ作成日時（ISO 8601形式）。
- **`sources`**: 根拠となったWiki内ソースファイルへのリンク（例：`[[sources/論文名.pdf]]`）。

---

## 3. 執筆ガイドライン

### 3.1 構成案
1. **H1タイトル**: 用語名または記事名。
2. **要約コールアウト**: `> [!abstract] 要約` 形式で、冒頭に配置。
3. **詳細解説**: 専門的かつ客観的な記述。英語の専門用語（Self-RAG, Retrieval等）は英語表記を優先する。
4. **内部リンク**: 本文中の重要用語には積極的に `[[用語名]]` の形式でリンクを付与する（Wikipediaスタイル）。

### 3.2 自律修復 (Linting)
- **Red-linkの解消**: リンクは存在するが実体がない用語を自動検知し、新規ページを起稿する。
- **統合 (Merge)**: すでにページが存在する場合、既存の記述を尊重しつつ、新しい知見を `> [!info] AIからの更新提案` として追記する。

### 3.3 厳格な根拠付原則 (Strict Grounding Principle)
- **一次情報への完全依拠**: 作成されるすべての解説（特に `wiki/concepts/` の用語解説）は、**投入された文献（PDF等）の事実のみ**に基づいて記述します。
- **外部知識の遮断**: 文献から読み取れない詳細な仕組み、歴史、実装、コード例などは、AIの事前学習知識から勝手に肉付けしてはなりません。
- **簡潔なスタブ化**: 文献上の言及が薄い（例：単にベンチマークや引用元として名前が出ているだけなど）場合は、詳細な章立てを捏造して肉付けするのを避け、**文献の事実に基づく簡潔な記述（必要十分なスタブ）**に留めます。
- **ハルシネーションの防止**: 略語（例: "ACL"）の解釈において、一般的なIT用語（Access Control List）と混同せず、投入された文献の文脈（Association for Computational Linguistics）に即した正確な事実のみを記載します。

---

## 4. 人間によるレビュー (HITL)

AIはあくまで「執筆案」を作成するエディターです。最終的な知識の確定は人間が行います。

1. **未審査状態**: `tags: [未審査]` が付与されたページは、検索DB（Qdrant）への同期対象外（または低優先度）となる。
2. **承認**: 人間が内容を確認・修正し、`未審査` タグを削除した瞬間、そのページは「公式な知識」として承認されたと見なされる。
3. **同期**: 承認済みページは `main.py --sync` によってベクトルDBへ反映され、RAGの根拠として利用可能になる。

---

## 5. 禁止事項
- **要約の欠落**: `description: ---` や `description: なし` といった不誠実な生成。
- **メタデータの汚染**: エイリアス欄への無関係な技術用語の羅列。
- **人間が書いたメモの削除**: `## 💡 人間の考察` セクションなどをAIが上書き・削除することは厳禁。

---

## 6. Gitリポジトリ管理上の注意 (Git Management)
- **データとコードの分離（メインリポジトリ）**: `wiki/` ディレクトリ配下のすべてのファイルおよびサブディレクトリ（`wiki/concepts/` の概念解説、`wiki/sources/` の論文等の一次資料、`wiki/raw_markdown/` 等を含むすべてのMarkdown・画像・その他ファイル）は、本システムの成果物・データです。主たるソースコードリポジトリのGit管理対象からは完全に除外（Ignore）されます。
- **入れ子型（Nested）Git構造**: `wiki/` ディレクトリ自体はメインリポジトリとは**完全に独立した別のGitリポジトリ（Nested Git Repo）**として初期化されています。Wikiデータの履歴管理や手動・自動コミット（`core/git_utils.py` による自動コミットなど）は、この独立した `wiki/` リポジトリ側で行われます。
- **.gitignoreによる除外**: メインリポジトリ側では `wiki/` 全体が `.gitignore` に登録されており、意図的に追跡を無視します。コードの編集・保守の際、`wiki/` 配下のファイルをメインリポジトリ側のコミットに含めないようにしてください。
- **インデックスからの除外**: 歴史的な経緯でメインリポジトリ側で追跡対象になっていたファイル（`wiki/Home.md` や `wiki/log.md`）は、すでに `git rm --cached` によってGitインデックスから完全に除外（Untrack）されており、メインリポジトリがコード専用に保たれるようになっています。
