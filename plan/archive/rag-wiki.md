# md-wiki 統合設計・進化計画書 (v1.0 & Beyond)
**〜 知能的協調型ナレッジベース：120B推論とハイブリッドRAGの融合 〜**

## 概要
md-wiki は、ローカルLLM (Gemma 4) とクラウドAPI (Sakura 120B) を適材適所で使い分け、投入されたドキュメントを永続的な知識（Wiki）へと「コンパイル」する知的システムである。
ObsidianをIDE、AIをプログラマー、Wikiをコードベースと見なし、人間とAIが協調して知のネットワークを成長させる。

---

## 1. コア・アーキテクチャ：Raw + Compiled ハイブリッド RAG
本システムは「情報の解釈」と「生の事実」を分離して保持し、推論時にそれらを再統合する。

- **Raw Source レイヤー**: Docling で抽出された生の全テキスト。細かい数値や事実の裏付けに使用。
- **Compiled Wiki レイヤー**: AI が要約・構造化し、人間が承認した知識のハブ。トピックの全体像と文脈の把握に使用。
- **同期 (Sync)**: Wiki フォルダ（実ファイル）を正 (Source of Truth) とし、Qdrant インデックスは常にそこから復元可能な「影」として運用する。

---

## 2. 知識の構造化：Wikipedia 形式のリンク密度
「単なる要約」から「知のネットワーク」への進化のため、以下のリンク戦略を強制する。

- **Wikipedia-style Linking**: 文中のあらゆる重要概念を `[[ ]]` で囲み、リンクの網の目を構築。
- **自律的リンク追跡**: AI がドラフト作成時、文書内のリンク先ページを能動的に読み込み、文脈の連続性を確保する。
- **Red-link 検知**: リンクはあるが実体がない概念を `lint` で抽出し、ナレッジの欠落を可視化。

---

## 3. ユーザーインターフェース (UX)
2つのインターフェースを役割に応じて使い分ける。

- **Obsidian (閲覧・編集)**: 
  - ナレッジのグラフ表示、PDFとMDの同時閲覧、手動での深い洞察の追記。
  - `## 💡 人間の考察` セクションは AI による更新から永久に保護される。
- **Streamlit Dashboard (制御・対話)**:
  - インジェストのトリガー、チャット形式での RAG 活用、DB 同期、健康診断の実行。

## 4. 進化のロードマップ

### v1.0: 基盤の完成 (Current)
- [x] Sakura API (120B) / Gemma 4 による高品質執筆。
- [x] Raw + Wiki ハイブリッド・インデックス。
- [x] Streamlit UI による基本操作とチャット。
- [x] Git による履歴の完全分離管理。

### v1.1: 運用の自律化と高速化
- **Git 駆動差分同期**: `git diff` を活用し、手動編集したファイルのみを瞬時に Qdrant へ反映。
- **バックグラウンド・キュー**: UI でアップロードしたファイルを非同期で順次パース。
- **Red-link 自動起稿**: 未作成の重要概念ページを AI が自動で下書き。

### v1.2: インテリジェント・メンテナンス
- **監査ノード (Audit)**: Layer 3 LLM が AI の変更を自動レビューし、人間は「重要な競合」のみに対処。
- **ナレッジ・グラフ統合**: ダッシュボード上での動的な知識マップ表示。
- **定期要約 (Landscape)**: 特定トピックの成長を毎週自動でまとめ直し、洞察を生成。
